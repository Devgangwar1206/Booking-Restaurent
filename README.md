# 🍽️ Restaurant Booking & Order Management — Backend

> A Spring Boot REST API for restaurant table pre-booking, food pre-orders, admin management, email integration, and CRUD operations.

This backend powers a full-stack restaurant platform where customers can reserve tables in advance, add food items to their cart, submit customized food requests, and place food pre-orders along with their table booking.

The application also provides an admin portal for managing customer bookings and incoming orders.

---

## 📌 Project Overview

The backend is built using **Java and Spring Boot** and follows a layered architecture consisting of:

- Controllers
- Services
- DTOs
- Entities
- Repositories
- Exception Handling
- Security Configuration

The backend exposes REST APIs consumed by the React frontend and persists application data in **PostgreSQL**.

```text
                    React Frontend
                          │
                          │ REST API
                          ▼
                ┌───────────────────┐
                │    Spring Boot    │
                │                   │
                │   Controllers     │
                │   Services        │
                │   DTOs            │
                │   Security        │
                │   Exceptions      │
                │   Repositories    │
                └─────────┬─────────┘
                          │
                          ▼
                     PostgreSQL
```

# ✨ Key Features

## 🍽️ Table Pre-Booking

Customers can reserve a table through the restaurant website by providing:

- Full Name
- Email
- Phone Number
- Date
- Time
- Number of Guests
- Table Preference
- Special Request
- Order Preference

Each successful booking receives a unique booking ID.

Example:

```text
BK-A1B2C3D4
```

The booking ID is generated by the backend using UUID-based generation.

---

## 🛒 Food Cart & Pre-Ordering

Customers can add food items to their cart before booking their table.

Each booking can contain multiple food items.

The backend stores these items using a relationship between:

```text
Booking
   │
   └── BookingItem
          ├── Menu Item ID
          ├── Name
          ├── Price
          └── Quantity
```

This allows a customer to submit both:

- Table reservation
- Food pre-order

as part of the same booking workflow.

### 💳 Payment

The application does **not process online payments**.

Customers can pre-book their table and submit their food order through the website, but payment is completed at the restaurant.

# 🧑‍💼 Admin Portal

The project includes an admin portal connected to the Spring Boot backend.

The administrator can access booking/order information submitted by customers.

The admin workflow allows management of:

- Customer bookings


# 📡 REST API

## Booking APIs

### Create Booking

```text
POST /create
```

Creates a new restaurant booking.

The request can contain customer details, table preferences, special requests, order preferences, and cart items.

---

### Get Booking By ID

```text
GET /read/{id}
```

Returns a booking using its database ID.

---

### Get All Bookings

```text
GET /read
```

Returns all bookings stored in the database.

---

### Update Booking

```text
PUT /update/{id}
```

Updates an existing booking using its database ID.

---

### Delete Booking

```text
DELETE /delete/{id}
```

Deletes a booking using its database ID.

# 📦 DTO Layer

The project uses **Data Transfer Objects (DTOs)** to separate API request/response models from database entities.

Current DTOs include:

```text
dto/
│
├── BookingItemDto.java
├── ContactRequestDto.java
├── CreateRequestdto.java
├── CreateResponsedto.java
├── ExceptionResponseDto.java
├── UpdateRequestdto.java
└── UpdateResponsedto.java
```

DTOs are used to control the data exchanged between the frontend and backend and provide a cleaner API structure.

---

# 🗄️ Entity Model

The main booking entity contains customer, reservation, order, and timestamp information.

```text
Booking
│
├── id
├── fullName
├── email
├── phone
├── date
├── time
├── guests
├── tablePreference
├── specialRequest
├── orderPreference
├── bookingId
├── createdAt
└── cartItems
      │
      └── BookingItem
```

### Booking → BookingItem

The relationship is implemented as:

```text
One Booking
      │
      ├── Food Item 1
      ├── Food Item 2
      ├── Food Item 3
      └── ...
```

This allows one booking to contain multiple pre-ordered food items.

The relationship uses cascade operations and orphan removal so that cart items are managed along with their parent booking.

# ⚙️ Running Locally

## Prerequisites

Make sure you have:

- Java 17+
- Maven
- PostgreSQL
- Git

---

## 1. Clone the Repository

```bash
git clone <repository-url>
```

Navigate to the backend directory:

```bash
cd backend
```

---

## 2. Database

Create a PostgreSQL database for the application.

The backend is configured to use PostgreSQL as its relational database.

Database credentials and email credentials should be configured locally or through environment variables.

---

## 3. Start the Application

Run the Spring Boot application using Maven:

```bash
mvn spring-boot:run
```

Or run the main Spring Boot application class directly from your IDE.

The backend runs on:

```text
http://localhost:8050
```
